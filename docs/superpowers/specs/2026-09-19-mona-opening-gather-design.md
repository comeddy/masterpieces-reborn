# 04번 After Leonardo — Mona Lisa 오프닝 응집 안무 설계

- 날짜: 2026-09-19
- 대상: `js/pieces/04-mona-lisa.js` (단일 파일) + `test/mona-opening.test.mjs`
- 브랜치: `feature/mona-opening-gather` (master f1d093c 기반)

## 배경 (사용자 피드백)

"처음 시작할 때 얼굴 부분 구역에 점이 모이는 게 어색하다. 모든 점이 시작할 때 자연스럽게
모여 그림을 만들어 달라. 특히 얼굴은 미소로 웃는 상."

베이스라인(master) 오프닝을 시간대별로 캡처해 확인한 원인 세 가지:

1. 얼굴 박스(u 0.30~0.68, v 0.10~0.45)에 2차 고밀도 샘플(≈6배)을 덧얹어, 응집 중 2~3초에
   박스 입자가 밝은 additive 덩어리로 뭉치고 5초엔 직사각형 경계가 그대로 드러난다.
2. 얼굴 타원 입자만 스프링 0.4배(과감쇠)라 수 초를 기어가며, 타원 안이 검은 구멍으로 남는다.
   판별이 이진(안/밖)이라 구멍 경계가 날카롭다.
3. 얼굴 렌더 패스도 박스 불리언(isFace)으로 갈려 정지 상태에서도 박스 단차가 보인다.

## 확정된 설계

모든 얼굴 관련 처리는 얼굴 타원의 정규화 거리 d(0 중심, 1 경계)로 정의된 **연속 필드**다.

### 1. 샘플링 — 내용 기반 밀도 + 특징 보존 (`samplePixels`, 순수) · 2026-09-20 개정

> **개정 배경**: 9월 19일 배포판(얼굴 타원 3배·입 5.5배 격자)에 대해 사용자가 "얼굴 주변만 점 밀도가
> 높다"고 지적. 얼굴 타원 기하로 밀도를 올리면 머리 주변 배경까지 촘촘해져 고리가 보인다. 세 안(에지
> 중요도 / 밝기+에지 중요도 / 배포판)을 같은 조건으로 캡처해 비교한 뒤 **밝기+에지 중요도**를 채택.

- 미세 격자(간격 step/√DENSITY_MAX, DENSITY_MAX 2.8)로 전 영역을 훑어 셀마다 3×3 평균 명도의 평균
  (밝기)과 최대−최소(명암폭)를 재고 중요도 `imp = W_BRIGHT·밝기^BRIGHT_GAMMA + W_EDGE·min(1, 명암폭/EDGE_NORM)
  + W_FACE·faceWeight·skinness` (1.0 / 1.5 / 0.8 / 60 / 1.5)를 만든다.
  - 밝기·경계만으로는(W_FACE 0) 실자산에서 얼굴 1.46 · 가슴 1.77 · 하늘 1.33 · 입 1.60 배가 되어
    가슴이 초상의 초점을 가로채고 미소가 약해진다(캡처 확인). 얼굴 항은 얼굴 타원 가중치에
    **피부빛(skinness: 적−청 차·명도)** 을 곱해 하늘·머리카락은 0이 되게 한다 — 기하만으로 올리던
    배포판의 머리 옆 하늘 고리가 생기지 않으면서 얼굴·목 피부만 촘촘해진다.
  - 실자산 실측 밀도 배율(기본 격자 1 기준, W_FACE 1.5): 얼굴 2.18 · 입 2.46 · 눈 2.67 · 가슴 1.69 ·
    하늘 1.24 · 손 0.97 · 드레스 0.90. 채택 확률 `p = min(1, DENSITY_FLOOR + K·imp)`(하한 0.2 → 최저 밀도 0.56배),
  K 는 총량이 `count·DENSITY_TOTAL`(12,000×1.2 ≈ 14,400, 배포판과 동일)이 되도록 이분 탐색(`solveK`).
- 어두운 바탕의 점묘는 빛을 찍는 것이라 밀도가 원작의 빛을 따르면 얼굴·가슴·손이 함께 촘촘하고 어두운
  드레스·머리카락은 성긴다 — 얼굴만 특별 취급하지 않으므로 머리 주변 고리가 없다. 경계 항으로
  눈·입술선·손가락 윤곽·소매 주름이 조금 더 촘촘해져 미소 정보는 배포판과 동등(관람 거리 블러 대조).
- 특징 보존: 명암폭 ≥ FEATURE_EDGE(12)인 채택 셀만 최암점 스냅 후보. 임계는 FEATURE_CONTRAST(35),
  입 서브필드 중심에서 MOUTH_FEATURE_CONTRAST(18). 평탄 셀은 지터 위치에 원색(격자 무늬 방지).
- 각 점은 상대 밀도 `dens = p·DENSITY_MAX`를 가진다. 렌더는 이동 중 헤일로·코어 알파를 `1/dens`
  (0.4~1.6 클램프)로 나눠 밀도가 높은 곳이 홀로 밝은 안개 덩어리로 뜨지 않게 한다(정지하면 1).
  구현은 `DENS_BUCKETS = [0.56, 1.0, 1.7, 2.8]` 4단계 양자화 + 입자를 버킷으로 한 번 정렬(그리기 순서만) —
  이동 중(모두 MONO 색) 연속 입자의 fillStyle 문자열이 같아 캔버스 색 파싱 비용이 준다(오프닝 p50 10.5→5.2ms).
- 입 서브필드(`MOUTH`)는 밀도를 올리지 않고 특징 임계·밝은 점 확대 억제에만 쓴다.
- 폐기: FACE_BOOST(얼굴 격자)·MOUTH_BOOST(입 격자). 아래 원 설계 §1은 이력용.
- 검증 사고 기록: 대안 비교 때 1-b 스파이크 서버(8099)가 다른 세션의 서버와 포트가 겹쳐 뜨지 못했고,
  캡처는 그 서버(배포판 코드)를 찍었다. 그래서 처음 보여 준 "1-b" 시트는 배포판과 같았다. 이후 서버
  pid·로그 확인을 캡처 절차에 넣고, 실제 1-b(밝기+경계만)를 다시 캡처해 위 결론을 얻었다.

#### (이력) 2026-09-19 원 설계 §1 — 균일 격자 + 경계 없는 얼굴 밀도 + 특징 보존

- 기본 격자: 전 영역 동일 간격, 목표 12,000 / reduced 7,400 — 베이스라인 총량(7,000+5,000 / 4,200+3,200)과
  같고, 미병합 브랜치 feature/mona-uniform-dots의 스펙 `2026-07-12-mona-uniform-dots-design.md`(커밋 82f0c0b)에서
  사용자가 택한 "총량 유지 균일 재배분"을 따른다. 얼굴·입 격자 가산으로 실제 총량은 약 14,500이며, 엔진의 화면
  면적 캡(`w*h/110`, 1600×900이면 13,090)이 shuffle 뒤 균일하게 잘라 밀도 비율은 유지된다.
- 얼굴 격자: 간격 step/√FACE_BOOST의 두 번째 격자를 얼굴 필드 안에서 가중치 확률로 채택 →
  밀도가 1 → FACE_BOOST(3.0)배로 smoothstep 연속 증가. 경계는 없다.
  - 근거: 1600×900 화면에서 기본 격자 간격 ≈5.4px인데 미소의 입꼬리 곡률은 ≈3px로
    **간격보다 작다**. 균일 밀도로는 원리적으로 해상되지 않아 얼굴만 촘촘해야 한다.
    2.2배·3.0배 후보를 관람 거리(블러) 비교로 대조해 3.0배를 채택.
- 특징 보존: 얼굴 필드 셀은 3×3 평균 명도를 훑어 "셀 평균 − 최암점 ≥ FEATURE_CONTRAST(35)"인
  특징 셀만 최암점에 스냅(입술선·눈꺼풀·콧구멍 그늘이 지터에 묻히지 않음). 평탄한 피부 셀은
  지터 위치 + 3×3 평균색(1px 크라클뢰르 필터). 평탄 셀까지 스냅하면 동률 픽셀로 몰려 격자
  무늬가 생기므로 제외.
- 입 서브필드(`MOUTH` 타원, `mouthWeight`, 감쇠 대역 d 1→1.8 — 얼굴 타원 안에 머무는 최대):
  판정 패널이 "입이 수평 띠로만 읽힌다"고 확인한 뒤 추가. 세 번째 격자로 입 중심 밀도를
  MOUTH_BOOST(5.5)배까지 연속 상향, 특징 임계를 입 중심에서 MOUTH_FEATURE_CONTRAST(18)로
  낮춰 저대비 입꼬리 그늘도 스냅, 밝은 점 확대를 입 중심에서 80% 억제해 입술선을 덮지 않게.
- 같은 픽셀은 한 번만 넣는다.

### 2. 얼굴 필드 렌더 (`faceWeight`)

- `p.fw = faceWeight(d)`: 타원 안 1 → d 1.6에서 0(smoothstep). 박스 불리언 제거.
- 3패스 모두 p.fw로 섞임: 헤일로 소멸 `1 − fw·coh`, 코어 기본 알파는 전 입자 동일(0.34, 얼굴 전용 분기 없음)에
  `1 − fw·coh`를 곱해 응집한 얼굴 점만 연속 소멸(패스 3이 덮음),
  source-over 점묘 알파 `(0.42 + 0.53·coh)·fw`, 대비 확장 `1 + 0.3·coh·fw`.
- 점 크기: 밝을수록 크게(`1 + 0.6·bright·coh·fw`) — 어두운 바탕의 점묘는 빛을 찍는 것이라
  피부는 톤으로 이어지고 눈·입술선은 작은 어두운 점(틈)으로 남는다.
- 이동 중 입자(이동 계수 lf: 목표 거리 70px에서 1, 전역 fog와 max) 헤일로·코어 알파 45% 감쇠
  (오프닝 첫 1초는 0→45% 램프해 시작 순간부터 점이 보임) — 연기가 눈부신 폭풍이 아니라
  어스름한 안개에서 형상이 응결해 나온다. 이동 중 얼굴 필드는 밀도가 FACE_BOOST배라 면적당
  밝기도 높아지므로 `1/(1+(FACE_BOOST−1)·fw)`로 나눠 몸과 같은 안개가 되게 한다.
- 얼굴 점묘 패스(source-over)는 `(1 − lf)`로 이동 중 완전히 사라진다 — 판정 패널이 "재응집
  중 얼굴이 홀로 밝은 타원 덩어리로 떠 있다(렌더가 안무와 반대)"고 확인해 수정. 이동 중
  얼굴 입자도 패스 1·2의 안개로만 보이고, 응집도가 오르며 점묘가 떠오른다.
- 비용: 정지 입자(lf<0.03)의 rgba 문자열·반지름을 응집도 양자화 키(32단계)로 입자에 캐시,
  이동 계수는 updateFog에서 프레임당 1회 계산해 3패스가 공유, 정지·응집한 얼굴 점의 코어
  패스는 `(1 − fw·coh)`로 소멸시켜 그리지 않는다(패스 3이 덮음). 헤드리스 측정(그리기 스텁,
  JS만): 유휴 1600×900 6.1ms / 1080p 7.2ms (master 7.7 / 7.8), 오프닝 6~7ms (master 5~6ms),
  클릭 산란 직후 19~23ms (master 15ms — 이동 중 arc 수 29k vs 24k, fillStyle 파싱이 지배적).

### 3. 응집 안무 (`gatherDelay`, `gatherSpring`, `faceSpringScale`)

- 입자별 지연 `delay = (1.2s + 0.45s·rnd) · (1 − smoothstep(0.35, 3.0, d))` — 얼굴 중심이 가장
  늦고 바깥(d ≥ 3.0)은 0(지터도 같은 기울기로 감쇠해 도달 거리에서 계단이 없다). 지연 중
  스프링 20%(멈추지 않고 연기처럼 계속 흘러감) → 지연 뒤 0.4초 smoothstep 램프로 전강성.
  판정 패널 반영: 도달 거리 2.4→3.0·유휴 스프링 8→20%로 이동 중 얼굴 필드가 독립 덩어리로
  보이지 않게, 지터 0.25→0.45초로 얼굴이 강체처럼 함께 움직이지 않게.
- 상시 스프링은 이진 0.4 → 연속 `1 − 0.15·faceWeight(d)`(중심 0.85). 감쇠 3.4에서 지수
  감쇠율은 스프링과 무관하게 c/2 = 1.7/s라 0.6 이하로 내려도 "얼굴 마지막"이 아니라 "수 초
  기어감"만 생긴다(테스트로 확인).
- 오프닝과 클릭 산란 후 재응집이 같은 안무(startGather). 드래그 휘젓기는 재시작하지 않고,
  연타는 산란만 누적하며 안무는 0.3초 안에 다시 시작하지 않는다(얼굴 스프링 무한 유예 방지).
- 결과 타임라인(1600×900): ~3초 몸·배경 안착, 4~5초 머리 응결, ~7초 얼굴 또렷.

### 4. 카메라 손짓 (2026-09-20 추가)

- 사용자 요청: "03번처럼 카메라로 체험하기". 01번(가나가와)과 같은 **셸 합성 포인터(handPointer)** 방식을
  택한다 — `data.js` 04번에 `cam: true, handPointer: true, camHands: 1`. 셸이 손을 포인터 규약으로
  합성하므로(펼친 손 = down, 주먹→펼침 = justDown, 손 위치 = x/y) 작품의 기존 마우스 경로가 그대로
  손짓 경로가 된다: 작품의 마우스 입력 규약(down = 휘젓기, justDown = 안개 폭발 scatter → 같은 응집
  안무로 얼굴이 마지막에 돌아옴)을 그대로 타되, 휘젓기의 세부는 손 전용이다(아래 불릿 — swirl 대신 방사
  밀림 + 의사 컬). 손이 얼굴 위에 펼쳐져 머무르면 그 자리 안개가 계속 살랑여 얼굴이 흐려지고, 손을 떼면
  다시 또렷해진다.
- 작품 고유 처리 — 손은 **손바람**: 손은 보이는 동안 늘 "펼침(down)"이라 마우스의 소용돌이(엔진 swirl은
  프레임마다 속도를 누적 가산)를 그대로 쓰면 15% 세기라도 몇 초 만에 초상 윗부분이 거대한 고리로 말린다
  (E2E 두 차례 확인). 그래서 손 경로는 swirl을 쓰지 않고, 손 속도에 비례한 방사 밀림(scatter,
  `handMotion(speed)`: 80px/s 이하 0 → 600px/s 이상 1)과 손 아래 안개의 살랑(의사 컬, 멈춘 손은
  `HAND_STILL` 0.15)만 준다. 세기는 펼침 정도 `handStir(openness)`(반쯤 0.35 → 활짝 1)로 조절하고
  dt·60으로 프레임률에 무관하게 한다. 멈춘 펼친 손은 그 자리 얼굴을 살랑 흐리고, 저으면 안개가 밀려난다.
  마우스 드래그의 소용돌이는 기존 그대로. 좌표가 비정상(NaN)인 프레임은 입력 무시(11번과 같은 가드).
- 하지 않는 것: 우하단 카메라 미러(사용자 피드백으로 전 작품 미표시), 랜드마크 직접 소비(03번의
  핀치 같은 별도 제스처 없음 — 마우스 규약과 1:1 대응을 유지해 힌트 한 줄로 설명되게).
- 문구: note에 카메라 문장 추가, hint는 📷 우선·마우스 대응 명시(01번 형식). README 사용법 한/영 추가.
- 검증: 순수 `handStir` 테스트, data.js 플래그 테스트, 헤드리스 E2E(가짜 MediaPipe 번들
  `window.__CAM_CDN__` 시임 + Chrome 가짜 카메라 장치) — 📷 켜기 → 펼친 손이 얼굴 위를 지나가며
  안개가 휘저어지는지, 주먹→펼침에 산란이 일어나는지 캡처로 확인.

   시뮬레이션)와 순수 샘플러(얼굴·입 밀도 배율·감쇠 대역 단조·어두운 선 보존·중복 없음·평탄
   셀 분산) 14개 추가 (전체 103개 통과).
2. 헤드리스 Chrome 캡처(독립 playwright-core): 오프닝 0.3~10초 시트, 클릭 재응집 시트,
   얼굴 3배 확대 원작 대조, 관람 거리(블러) 대조. 베이스라인과 나란히 비교.
3. 판정 패널(5개 렌즈 × 회의론자 2명 반박 검증): 확인된 9건 중 미소 미판독·재응집 타원
   덩어리·강체 이동·유휴 프레임 비용을 위 설계에 반영. 남긴 것: 클릭 산란 직후 2~3초의
   이동 중 프레임 비용(master보다 arc 20% 많음), 폴백 실루엣(자산 로드 실패 시)의 얼굴
   타원이 FACE_OVAL과 어긋남(master부터 있던 문제, 절차적 폴백 한정).
